Paper explainer

How Much Do Language Models Memorize?

Morris, Sitawarin, Guo, Kokhlikyan, Suh, Rush, Chaudhuri & Mahloujifar — FAIR at Meta, Google DeepMind, Cornell, NVIDIA (2025). arXiv:2505.24832

The Big Picture

Modern language models are trained on staggering amounts of text, yet their weights are a fixed, comparatively tiny number of parameters. That raises a very concrete question: when a model gets good at predicting text, how much of its skill is just rote storage of the training examples it saw, versus genuine, reusable understanding of language? And is there a hard limit to how much a model can store, measured precisely, in bits?

This paper answers both questions with a single number: GPT-style transformer language models can store approximately 3.6 bits of information per parameter p.1. That's not a vague estimate — the authors derive a formal, information-theoretic definition of memorization, then measure it directly by training hundreds of models on data whose exact information content they control.

Key idea

The paper splits everything a model "knows" about its training data into two pieces: unintended memorization (information about one specific dataset that doesn't generalize) and generalization (information about the true pattern behind the data, which any well-trained model would pick up). Once you can measure these separately, in bits, you can define a model's total capacity — the most it can ever unintentionally memorize — as a real, measurable property of the architecture and precision, not just a vibe.

Analogy

Think of a model's parameters as a fixed number of shelves in a storage room. While you have more shelves than items, you can give every item its own shelf — pure memorization. Once the number of items outgrows the shelves, you're forced to start grouping similar items together and keeping only a shared description of each group instead of every item individually. That shared description is generalization — and the paper finds the switch-over point is remarkably sharp, not gradual.

Why it matters: regulators, researchers, and practitioners constantly ask whether a language model "memorized" a particular document (for privacy or copyright reasons). Prior approaches tried to answer this by seeing whether a model could be prompted to output the text verbatim — but that confuses memorization with a model simply being capable of producing a string for other reasons (the paper's own example: a model that computes 2^100 correctly hasn't necessarily "memorized" that fact — it may have generalized the rule of exponentiation) p.3. This paper instead gives a precise, bit-level accounting that cleanly separates the two.

Background Concepts

Entropy and bits

Shannon's entropy H(X) measures how much uncertainty — equivalently, how much information, in bits — a random variable X contains. A fair coin flip carries exactly 1 bit of uncertainty; a predictable sequence carries close to 0. Crucially, you cannot (on average) compress samples from X into fewer bits than H(X) without losing information.

Mutual information extends this to two variables: I(X,Y) = H(X) − H(X|Y) is how many bits of uncertainty about X are resolved once you know Y. The paper's core trick is to treat memorization itself as a mutual-information quantity: how many bits about the training set are "resolved" by knowing the trained model p.4.

Kolmogorov complexity

Shannon entropy is defined for random variables — distributions you can sample from repeatedly. But in practice there is only one dataset and one trained model, both fixed, specific objects. To talk about the information content of a single, specific string, the paper turns to Kolmogorov complexity H^K(x): the length of the shortest program that outputs x exactly p.5. Given a reference object θ to use as a helper, H^K(x|θ) is the length of the shortest program that outputs x when it's allowed to consult θ.

Common misconception

"The model can be made to output this string, therefore it memorized it" is not a safe inference. The paper points out that models can be coerced into outputting almost any string with the right prompt, and that prompting tricks like "repeat cat 1000 times" obviously don't indicate memorization of "cat cat cat … cat" p.12. Generation ability alone is not proof of memorization — which is exactly why the paper insists on a compression-based, information-theoretic definition instead.

Compression as a practical stand-in

Exact Kolmogorov complexity is uncomputable, so the paper approximates it using arithmetic coding, a compression scheme whose achievable code length for a string is tied directly to how well a probabilistic model predicts that string (a classical result connecting prediction and compression, going back to Shannon) p.5. Concretely, the code length for x under a model θ̂ is approximated as its negative log-likelihood: H^K(x|θ̂) ≈ −log p(x|θ̂). This is what makes the whole framework measurable: a model's own loss on a sequence is an estimate of how many bits are needed to describe that sequence given the model.

Loss-based membership inference

The paper also uses a standard, simple privacy-style attack as a complementary measurement: pick a loss cutoff, and guess that any example scoring below it was in the training set p.9. Performance is reported as an F1 score, where 0.5 means the attack is no better than guessing. This loss-based membership inference (MI) will reappear as the subject of the paper's scaling law later on.

How It Works

Putting the background together, the paper defines two cleanly separated quantities for a dataset X, a "true" reference model Θ representing the real data-generating process, and a trained model Θ̂:

mem_U(X, Θ̂, Θ) = H(X|Θ) − H(X|(Θ,Θ̂))  (unintended memorization)

mem_I(X, Θ̂, Θ) = mem(X, Θ̂) − mem_U(X, Θ̂, Θ)  (generalization)

In words: unintended memorization is the extra information the model carries about X beyond what a model that only understood the general data-generating process would already know. Generalization is everything else — the useful, reusable part.

The reference/oracle-model trick

To actually compute this split, the paper needs a stand-in for "a model that only knows the true distribution." For synthetic data (Section 3 of the paper) that's easy: the true distribution is known exactly, since the authors generated it. For real text (Section 4), they instead use either an equal-sized model trained on the full, maximal dataset, or a bigger "oracle" model trained far past what the target model saw — whichever achieves the best (lowest-loss) compression on the data is used as the reference p.8. Subtracting its compression of x from the target model's compression of x isolates the "extra, sample-specific" bits.

Summing unintended memorization over every example in a dataset gives a lower bound on the dataset's total unintended memorization, and that total can never exceed the entropy of the trained model itself (Proposition 1, p.4) — a nice sanity check: you can't memorize more than the model's own information content. This lets the paper define capacity cleanly:

Capacity(L) = max over datasets X of mem(X, L(X))

i.e. the most unintended memorization achievable no matter how the dataset is chosen — measured in practice by training to saturation on datasets of increasing size and finding the plateau p.7. The appendix confirms this estimator is accurate: predicted vs. observed memorized bits agree to within about 1.7–1.8% average error when the authors vary sequence length or vocabulary size independently p.15.

From theory to a measurement pipeline

1

Sample a dataset

Either uniform random bitstrings (known entropy exactly) or real deduplicated text (FineWeb).

2

Train the target model θ̂

A GPT-2-architecture transformer trained from scratch on that dataset.

3

Score each example under θ̂

Estimate HK(x|θ̂) as −log p(x|θ̂) — the model's own negative log-likelihood.

4

Score each example under a reference model θ

The true distribution (synthetic case) or an oracle/full-data model (text case).

5

Subtract to get per-example unintended memorization

The gap between the two code lengths is the sample-specific information θ̂ carries about x.

6

Sum across the dataset

Bounded above by the model's own entropy (Proposition 1) — gives total dataset memorization.

7

Repeat across dataset sizes, find the plateau

The maximum over all dataset sizes is the model's capacity.

Experiments

(a) Synthetic uniform random bitstrings — isolating pure capacity

To measure capacity without any confound from generalization, the authors first train on datasets where every token is sampled uniformly at random, independent of everything else. There is no pattern to generalize to, so every bit the model retains about the training data is, by construction, unintended memorization p.7.

Setup: GPT-2-style transformers with 1–8 layers and hidden dimensions scaled from 32 to 512, giving models from about 100K to 20M parameters, trained for 10⁶ steps with batch size 2048 in bfloat16 on a single A100, vocabulary size V = 2048, sequence length S = 64, five random seeds per dataset size p.7.

(b) Real text — memorization vs. generalization

Repeating the setup on real text (the FineWeb dataset, with an extra deduplication pass — without it, truncating sequences to 64 tokens creates 1–2% near-duplicates, which would inflate apparent memorization) p.8, the picture changes: unintended memorization now rises and then falls as the dataset grows, instead of simply plateauing. Early on, the model fills its capacity with example-specific detail; once the dataset grows past capacity, the model starts substituting reusable, general patterns for sample-specific ones, and unintended memorization decreases even as the model keeps improving on held-out data p.8.

Double Descent / Grokking

The paper observes a sharp transition exactly where dataset size (in bits) crosses model capacity (in bits): test loss spikes right at a dataset-to-capacity ratio of 1, then falls again as the dataset grows further past capacity — the classic "double descent" shape p.3, p.9. Their explanation: once a model can no longer memorize every example individually, it's forced to share information between examples to save capacity, and that sharing is generalization p.9.

Three regimes

Dataset ≪ capacity: everything fits comfortably; the model memorizes point-for-point. Dataset ≈ capacity: the critical zone — this is where the double-descent peak in test loss appears. Dataset ≫ capacity: memorization is no longer enough; the model is forced to generalize, and test loss falls again.

Membership Inference Scaling Law

Beyond synthetic data, the paper fits a predictive scaling law for loss-based membership-inference performance, as a function of model capacity and dataset size p.10. As printed in the paper:

Membership_F1(θ, D) = ½·(1 + c₁·σ(c₂·(Capacity(θ)/|D| + c₃))),   σ(x) = 1/(1+e⁻ˣ)

with fitted constants reported in the paper as c₁ = 1.34, c₂ = −0.034, c₃ = −33.14, found with a non-linear least-squares solver on the text experiments from Section 4 p.10.

In plain English, the idea is: for a fixed model capacity, membership inference starts near-perfect on tiny datasets (easy to overfit, so train/test loss gap is large) and decays toward 0.5 — a coin flip — as the dataset grows, because differentiating train from test examples by loss alone gets harder p.10.

Extraction vs. membership inference

The paper separately measures exact-suffix extraction rates (can the model be greedily decoded into reproducing a held-out suffix given a prefix?) and loss-based membership-inference F1, across the same models and dataset sizes p.9. Both decline as the dataset grows, but membership inference stays substantially higher: in some cases the model's membership score reaches 0.97 even when the exact-suffix extraction rate is 0 p.9. In other words, failing to extract a verbatim continuation does not mean a model carries no detectable trace of having trained on an example.

Why deduplication matters

Without deliberate deduplication, truncating real text to fixed 64-token sequences creates 1–2% accidental duplicates, which inflates apparent memorization for reasons that have nothing to do with per-example learning p.8. With careful deduplication, the paper finds that at large enough dataset sizes, extraction rates converge almost exactly to the rate measured on completely unseen test data — meaning essentially all successful extraction at that scale is explained by generalization, not memorization of that specific example p.9. The paper also finds the examples that do get memorized most are disproportionately documents with rare, high TF-IDF content — in one 20M-parameter model's analysis, the twenty most-memorized training sequences out of over a quarter million were overwhelmingly non-English (Japanese, Chinese, Hebrew, Greek) text that the model couldn't amortize across many similar examples p.17.

Why This Paper Matters

For practitioners

It gives a concrete, bit-denominated way to reason about memorization risk instead of an informal "can I get it to output this string" test. It also offers a sobering, scale-dependent conclusion: at the tokens-per-parameter ratios common in modern LLM pretraining, loss-based membership inference on the average training example is predicted to be statistically powerless p.10 — but that doesn't mean no individual example is ever at risk. Rare, unusual, hard-to-amortize examples remain disproportionately memorized regardless of overall scale p.17.

For researchers

The paper supplies a rigorous, sample-level, training-algorithm-independent definition of memorization that cleanly separates it from generalization — something extraction-based and prompt-based definitions could not do without confounds p.20. It also offers a new, mechanistic explanation for why double descent happens: not as a mysterious property of gradient descent, but as the direct consequence of a model running out of room to memorize and being forced to share information across examples p.9.

The bigger picture

"How much did my model memorize?" moves from a qualitative judgment call to a measurable quantity in bits, grounded in classical information theory rather than ad hoc probing — a foundation other work on privacy, capacity, and generalization in language models can build on directly.

Glossary

Bit
The basic unit of information; the amount of uncertainty resolved by a single fair coin flip.
Entropy, H(X)
The expected number of bits needed to describe a sample from a random variable X; a measure of its uncertainty/information content.
Mutual information, I(X,Y)
H(X) − H(X|Y); how many bits of uncertainty about X are resolved by knowing Y.
Kolmogorov complexity, HK(x)
The length of the shortest program that outputs the specific string x exactly; the single-instance analogue of entropy. Uncomputable in general, approximated in this paper with compression.
Arithmetic coding
A compression algorithm whose achievable code length for a string is tied directly to a model's predicted probability of that string — used to approximate Kolmogorov complexity via a model's negative log-likelihood.
Unintended memorization
The information a trained model retains about a specific dataset that goes beyond what any model trained to understand the true data-generating process would already know.
Generalization (intended memorization)
The information a model retains about the true, underlying data-generating process rather than about any one specific dataset.
Capacity
The maximum amount of unintended memorization a model/training algorithm can ever hold, found by maximizing over all possible datasets.
Reference model / oracle model
A stand-in for "a model that only knows the true distribution," used to isolate unintended memorization by subtraction. In the paper, either the true data-generating distribution (synthetic data) or a large model trained on far more data (real text).
Double descent
The phenomenon where test loss rises then falls again as a model crosses a critical point — here shown to occur exactly when dataset size (in bits) exceeds model capacity.
Grokking
A related phenomenon where a model's generalization performance improves suddenly, well after it has already fit (memorized) the training data.
Membership inference
Guessing whether a specific example was part of a model's training set, in this paper via a simple loss-cutoff rule.
F1 score
The harmonic mean of precision and recall; used here to score membership-inference attack performance, where 0.5 indicates random guessing.
Extraction (extractable memorization)
Whether an adversarial or greedy prompt can make a model reproduce a specific training string verbatim.
Deduplication
Removing near-duplicate examples from a dataset so that apparent memorization isn't inflated by a model simply having seen the "same" example multiple times.
Sigmoid function, σ(x)
1 / (1 + e⁻ˣ); an S-shaped curve mapping any real number to the range (0, 1), used in the paper's membership-inference scaling law.
Tokens-per-parameter ratio
Total training tokens divided by parameter count; a common way to describe how much data a model was trained relative to its size.
Bits-per-parameter
Model capacity (in bits) divided by parameter count — this paper's headline measure of how much raw information a model architecture can store per weight.
bfloat16 / float32
Two numeric precisions used to store model weights; bfloat16 uses 16 bits per number, float32 uses 32. The paper finds this has a much smaller effect on memorization capacity than on raw storage size.
TF-IDF
Term Frequency–Inverse Document Frequency; a score that is high for documents containing words that are rare across the whole dataset, used here to show that rare-content documents are the most memorized.
d_model / width
The hidden dimension size of a transformer layer — one of the two axes (with depth) the paper varies to produce Table 1.
n_layer / depth
The number of transformer layers stacked in a model — the other axis varied in Table 1.
